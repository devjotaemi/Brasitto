Proximos passos recomendados

1. Aplicar schema no Supabase apos deploy
- Rodar o supabase/schema.sql atualizado.
- Confirmar que as RPCs create_order_with_items e get_customer_order_status foram recriadas.
- Criar um pedido real com observacao.
- Definir previsao no admin.
- Cancelar um pedido com motivo e consultar pelo cliente.

2. Validar fluxo real apos deploy
- Cliente cria pedido com produto ativo.
- Cliente nao consegue pedir quando a loja esta fechada.
- Admin altera taxa fixa de entrega.
- Pedido novo aparece no painel admin.
- Alteracao de status aparece na consulta do cliente.
- Motivo de cancelamento aparece para o cliente.
- Previsao aparece para o cliente.
- Owner acessa Configuracoes.
- Admin comum nao acessa controles exclusivos do owner.

3. Melhorar experiencia do admin
- Trocar campo livre de cancelamento por motivos predefinidos com opcao Outro.
- Exibir destaque visual quando pedido tiver observacao do cliente.
- Facilitar limpeza da previsao quando pedido atrasar ou mudar de fluxo.

4. Melhorar formulario do cliente
- Avaliar observacoes por item, se fizer sentido no futuro.
- Validar se observacao geral precisa de limite de caracteres.

5. Evoluir entrega
- Manter taxa fixa por enquanto.
- Avaliar bairros/regioes atendidos apenas quando a operacao precisar.

6. Melhorias tecnicas
- Adicionar testes E2E com navegador quando o projeto adotar Playwright ou ferramenta equivalente.
- Cobrir criar pedido, consultar pedido, loja fechada e alteracao de status em navegador real.
- Avaliar rate limit para consulta publica de pedido.
